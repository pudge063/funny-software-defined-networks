# ADR-0004. Отключать IPv6 в сетях под Floodlight

- **Статус:** Accepted
- **Дата:** 2026-10-08
- **Спецификации:** `openspec/specs/sdn-lab-environment` (требование «Обход
  дефекта pkt_mark в OF1.3 packet-in»)
- **Процесс:** [P9](./processes.md#p9-дефект-pkt_mark-и-его-обход)

## Контекст

При подключении сети к Floodlight по OF 1.3 коммутаторы переподключались
десятки раз за запуск, тест `linear-k4` не видел коммутатор s2 30 секунд.
Лог Floodlight:

```
OFParseError: Unknown value for discriminator typeLen of class OFOxmVer13: 82436
```

Расследование (`ovs-ofctl snoop` с момента старта коммутатора):

- `82436 = 0x00014204` – NXM класс `0x0001`, поле 33, длина 4: `pkt_mark`;
- поле приходит в `OFPT_PACKET_IN` для MLDv2-отчётов (icmp6 type 143),
  которые ядро отправляет с портов коммутаторов с `skb->mark = 0xd4`;
- OVS 2.17 передаёт ненулевую метку в match packet-in, loxigen-парсер
  Floodlight 1.2 её не знает и закрывает канал.

## Решение

Сеть с внешним контроллером собирается только через `common.make_net()`,
которая до `net.start()` вызывает `common.disable_ipv6()`:
`net.ipv6.conf.{all,default}.disable_ipv6=1` в namespace каждого хоста и
`net.ipv6.conf.<порт>.disable_ipv6=1` для каждого порта коммутатора.

### Рассмотренные альтернативы

- **OpenFlow 1.0.** Устраняет дефект (в OF 1.0 у packet-in нет match), но
  ломает TCP в Forwarding (ADR-0003). Отклонено.
- **Патч Floodlight/loxigen.** Требует пересборки контроллера и выходит за
  рамки работ. Отклонено.
- **Обнуление метки в OVS.** Нет штатного способа исключить `pkt_mark` из
  packet-in. Отклонено.

## Последствия

- После обхода `OFParseError` = 0, переподключений нет (проверено на
  linear-k4 дважды подряд).
- Сети под Floodlight работают только на IPv4. Для работ этого достаточно.
- Хосты больше не генерируют фоновый трафик (RS, MLD), из-за чего Floodlight
  не узнаёт о них до первого пакета. Это порождает проблему, которую решает
  ADR-0005.
- Сети с контроллером `c0` и в режиме STP не затрагиваются.
