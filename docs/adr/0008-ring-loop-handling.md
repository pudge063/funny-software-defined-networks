# ADR-0008. Петли в кольце: Floodlight или STP с опросом сходимости

- **Статус:** Accepted
- **Дата:** 2026-10-08
- **Спецификации:** `openspec/specs/lab4-mininet-topologies` (требование
  «Режимы работы кольца»)
- **Процесс:** [P6](./processes.md#p6-обработка-петли-в-кольце)

## Контекст

Кольцо из `n ≥ 3` коммутаторов содержит петлю. С learning-switch контроллером
широковещательные ARP циркулируют бесконечно (broadcast storm). Исходный
скрипт ждал фиксированно: 20 с для LLDP и 35 с для STP.

## Решение

- Режим по умолчанию – Floodlight: LLDP строит граф, broadcast идёт только
  по остовному дереву. Ожидание обнаружения связей настраивается
  (`--discovery-time`, 20 с), затем вызывается `announce_hosts` (ADR-0005).
- Режим `--stp` – без контроллера: `OVSSwitch(failMode="standalone",
stp=True)`. Вместо фиксированной паузы `wait_stp()` опрашивает
  `ovs-vsctl get Port <порт> status:stp_state` и завершается, когда все порты
  в `forwarding`, `blocking` или `disabled` (таймаут 60 с).

## Последствия

- Запуск со STP короче фиксированных 35 с, когда STP сходится быстрее, и
  надёжнее, когда медленнее.
- Тест `test_ring_stp_without_controller` проверяет наличие порта в
  `blocking` и `pingAll == 0`.
