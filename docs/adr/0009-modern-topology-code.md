# ADR-0009. Современный код топологий: build(), типизация, общий модуль

- **Статус:** Accepted
- **Дата:** 2026-10-08
- **Спецификации:** `openspec/specs/lab4-mininet-topologies`
- **Процесс:** [P5](./processes.md#p5-запуск-скрипта-топологии)

## Контекст

Скрипты lab 4 были написаны в стиле методички под Python 2: переопределение
`Topo.__init__`, `irange`, `'h%s' % i`, `super(Cls, self)`, словари
параметров без типов, без проверки аргументов CLI. Код нельзя было
переиспользовать в тестах: сеть создавалась и проверялась внутри `main()`.

## Решение

- Топологии переопределяют `Topo.build()` – так рекомендует Mininet 2.2+, и
  именно его вызывает `Topo.__init__`.
- Типы: `LinkOpts` (TypedDict) для параметров `TCLink`, `ControllerAddr`
  (NamedTuple) для контроллера, DPID – hex-строка (`dpid()`), аргументы CLI –
  `positive_int`, `parse_controller`.
- Общий код – `reports/lab4/topologies/common.py`; сборка сети с внешним
  контроллером – только через `make_net()` (ADR-0004, ADR-0005).
- Каждый скрипт – и исполняемый файл, и модуль: класс топологии, функция
  запуска (`simple_test`, `perf_test`, `run`), `main()`, `net.stop()` в
  `finally`.
- Порядок `addHost`/`addSwitch`/`addLink` сохранён: от него зависят номера
  портов в отчёте.

## Последствия

- Тесты импортируют топологии напрямую (`pythonpath` в `pyproject.toml`).
- Фрагменты кода в `reports/lab4/report.md` обновлены и должны оставаться
  синхронными с кодом.
- Минимальная версия Python – 3.10 (синтаксис `X | None` в аннотациях
  работает через `from __future__ import annotations`).
